# RFC-0002: Brand Messaging & Go-To-Market Architecture

**RFC ID:** RFC-0002
**Version:** 1.0
**Status:** Draft
**Owner:** Brand is Code — Strateeg
**Date:** 2026-07-09

---

## Context

RFC-0001 definieert Brand is Code als een **AI Information Architecture Partner** die SMB-bedrijven helpt hun bedrijfskennis te organiseren, begrijpen en activeren.

Echter: de huidige website, presentaties en outreach-materialen communiceren nog geen consistente merkpositionering die dit onderscheid duidelijk maakt.

Zonder een geïntegreerd messaging framework:
- Ziet de doelgroep Brand is Code als een generiek "AI-bureau".
- Ontbreekt de rode draad van website → offerte → portal → klantcommunicatie.
- Sluiten de naam "Brand is Code" en de content niet op elkaar aan.

Dit RFC legt de normatieve merkboodschap vast die alle content, copy en communicatie-uitingen moeten volgen.

---

## Decision

Brand is Code positioneert zich als:

> **De strategische partner die jouw bedrijfsdata en -processen omzet in een systeem dat werkt, groeit en beslissingen ondersteunt — met of zonder AI.**

### Merkbelofte (Brand Promise)

> Code en data zijn het fundament van elk bedrijf dat klaar is voor morgen. Wij bouwen dat fundament.

### Positioneringsstatement

Brand is Code helpt MKB-ondernemers met het bouwen van een **information architecture** — een systeem van verbonden bedrijfskennis, geautomatiseerde processen en slimme beslisondersteuning — zodat hun bedrijf schaalbaar, beheersbaar en AI-ready is.

### Naamsverklaring (voor externe communicatie)

**Brand** = het bedrijf, de identiteit, de waarde die je uitstraalt.
**Code** = het systeem dat dat bedrijf laat werken, groeien en beslissen.

Brand is Code = jouw bedrijf is een systeem. Wij bouwen dat systeem.

### Doelgroepen

| Segment                         | Profiel                        | Pijn                                | Gewenste uitkomst                 |
| ------------------------------- | ------------------------------ | ----------------------------------- | --------------------------------- |
| MKB directeuren                 | 5–50 FTE, ambitieus, druk      | Geen grip op data, processen ad hoc | Schaalbaar werkend systeem        |
| Marketingmanagers               | Data-hongerig, tool-moe        | Losse tools, geen verbinding        | 1 bron van waarheid, automations  |
| Makelaars / sector-specialisten | Relatiebedrijf, hoge repetitie | Admin overvloed, weinig inzicht     | AI-versnelling + structuur        |
| Scale-ups                       | >50 FTE, groeisnelheid         | Tech debt, silo's                   | Information architecture redesign |

### Message Pillars

1. **Code als fundament** — elk bedrijf heeft een systeem van uitvoering nodig.
2. **Data als kompas** — beslissingen op basis van feiten, niet gevoel.
3. **AI als versneller** — AI versterkt wat al werkt; het vervangt niet de basis.
4. **Architectuur als strategie** — hoe je informatie organiseert bepaalt hoe snel je kunt groeien.

### Tone of Voice

- Helder, direct, zelfverzekerd — geen buzzwords.
- Concreet en bewijs-gestuurd — altijd met een voorbeeld of resultaat.
- Menselijk en eerlijk — geen hype, wel urgentie.
- Nederlands als primaire taal, soms Engels voor technische exactheid.

### CTA-Architectuur per funnel-fase

| Fase          | Bezoeker doel       | CTA-tekst                                       |
| ------------- | ------------------- | ----------------------------------------------- |
| Bewustwording | Herkenning probleem | "Herken jij dit?" / "Lees hoe dit werkt"        |
| Overweging    | Vertrouwen bouwen   | "Bekijk wat we bouwen" / "Lees de case"         |
| Beslissing    | Contact of intake   | "Plan een strategie-call" / "Start jouw intake" |
| Klant         | Voortgang & waarde  | "Open je portal" / "Bekijk je sprint"           |

---

## Alternatives Considered

### A. Generieke AI-bureau positionering
Niet gekozen omdat RFC-0001 expliciet stelt dat Brand is Code géén AI-tools verkoopt.

### B. Technisch/developer merk
Niet gekozen omdat de primaire doelgroep MKB-directeuren zijn, geen developers.

### C. Afzonderlijke sub-brands per dienst
Niet gekozen vanwege fragmentatie van merkherkenning en onnodig complexe GTM.

---

## Consequences

**Positief:**
- Consistente merkervaring van website tot portal.
- Heldere differentiatie t.o.v. generieke AI-bureaus.
- Content factory heeft een normative basis.

**Negatief/Risico:**
- Bestaande website copy moet worden herschreven.
- Kost initiële copywriting investering.

---

## Compatibility with RFC-0001

Dit RFC is volledig afgeleid van RFC-0001:
- De positionering als "AI Information Architecture Partner" is de directe vertaling van RFC-0001's strategische richting.
- De message pillars volgen exact de RFC-0001 filosofie: Data First, AI Second, Integrate Don't Duplicate.
- De doelgroepen zijn consistent met de MKB-focus en het AI Enablement Platform concept.

Geen conflict.

---

## Security and Privacy Impact

Geen directe technische impact. Messaging-richtlijnen leggen geen nieuwe dataverwerkingen vast.

---

## Rollout and Rollback

**Rollout:**
1. Messaging framework intern goedgekeurd door PM → v1.0 Accepted.
2. Strateeg-agent past website copy aan op basis van dit RFC.
3. Content Factory gebruikt pillars als basis voor alle blogs en social content.
4. Frontend Developer verwerkt CTA-architectuur in website/portal componenten.

**Rollback:**
- Terug naar versie 0.x messaging via git; geen technische rollback nodig.
